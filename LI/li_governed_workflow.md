# LI-Governed Workflow Role

This repository participates in the LI-governed ecosystem as the IAM architecture and augmented-agency theory repo.

It should not be treated as a generic AI-agent project. Its purpose is to define how human cognitive continuity, re-entry, attention, judgment, and agency can be preserved across time while interacting with tools, models, agents, and generated artifacts.

## Ecosystem position

- `iamcoherence` names the public frame: proxy collapse, human leverage, and post-artifact agency.
- `augmented-agency` defines the deeper IAM architecture: continuity manifolds, runtime strata, ingestion, chewing, source boundaries, and human/agent distinctions.
- `li-governed-overlay-workflow` defines the operational method for safe LLM-assisted repo change.
- App or practice repos such as Take60, grazing, tax filing, and voice/context examples demonstrate the pattern in concrete domains.

## Practical governance rule

When an LLM assists this repo, it must work under the repo's LI rather than relying on platform memory or generic agent assumptions.

The expected pattern is:

1. read the relevant LI;
2. declare the working set;
3. make a bounded patch;
4. run or request verification;
5. regenerate the pack;
6. let the human review and commit.

## Invariants

- LI is normative; generated summaries are derived.
- The repo must preserve distinctions between agent execution and human agency.
- The repo must preserve continuity as a time-extended structure, not reduce it to static memory or retrieval.
- The repo must not imply that judgment is automated, reconstructed, or owned by the model.
- Generated context can assist re-entry, but the repo remains the continuity-bearing object.

## Return pattern

Future sessions should start from `prompts/return_to_work.md` and the current pack. The return prompt is not a replacement for LI; it is an entry point into the current working state and architecture.
